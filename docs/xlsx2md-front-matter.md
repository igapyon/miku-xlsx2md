# xlsx2md Front Matter Contract

This document defines the YAML front matter emitted at the beginning of
Workbook-level combined Markdown generated by `miku-xlsx2md`.

The contract is intended for humans, scripts, and AI agents that need to
identify the generated artifact, trace its source, and understand the
conversion settings before reading the full Markdown body.

## Scope

This front matter applies to saved combined Markdown and to the Markdown entry
inside ZIP output.

It does not apply to internal per-sheet Markdown fragments returned by the
product core before export composition.

## Output Shape

Combined Markdown always starts with YAML front matter, followed by the
Workbook heading and Sheet sections:

```markdown
---
title: "sales.xlsx"
description: "Excel workbook converted to Markdown by miku-xlsx2md."
type: converted
category: converted
topics:
  - converted
  - xlsx
  - markdown
  - miku-xlsx2md
  - workbook-conversion
status: generated
audience:
  - human
  - agent
  - maintainer
created: "2026-06-27"
updated: "2026-06-27"
sources:
  - type: local-file
    path: "sales.xlsx"
    role: primary
conversion:
  tool: miku-xlsx2md
  version: "1.2.0"
  output_mode: display
  formatting_mode: github
  table_detection_mode: balanced
  shape_details: exclude
---

# Book: sales.xlsx

## Sheet: Summary
```

## Field Contract

| Field | Shape | Meaning |
|---|---|---|
| `title` | string | Workbook file name used for conversion output. |
| `description` | string | Short fixed description of the generated Markdown role. |
| `type` | string | Stable artifact type. Current value: `converted`. |
| `category` | string | Stable document category. Current value: `converted`. |
| `topics` | string array | Stable grouping terms for search and agent routing. |
| `status` | string | Document lifecycle state. Current value: `generated`. |
| `audience` | string array | Intended readers. Current values: `human`, `agent`, `maintainer`. |
| `created` | `YYYY-MM-DD` string | Generation date. |
| `updated` | `YYYY-MM-DD` string | Generation date for this generated artifact. |
| `sources` | object array | Primary input provenance. |
| `conversion` | object | Tool and option metadata for this conversion. |

## Stable Values

Agents and scripts may treat these values as stable routing signals:

- `type: converted`
- `category: converted`
- `topics`
  - `converted`
  - `xlsx`
  - `markdown`
  - `miku-xlsx2md`
  - `workbook-conversion`
- `status: generated`
- `sources[0].type: local-file`
- `sources[0].role: primary`
- `conversion.tool: miku-xlsx2md`

## Source Path

For CLI output, `sources[0].path` is the input path passed to the CLI, not a
normalized absolute path.

This preserves a useful regeneration hint when the original command used a
relative path.

## Conversion Object

`conversion` records the settings that materially affect generated Markdown:

| Field | Shape | Meaning |
|---|---|---|
| `tool` | string | Tool name. Current value: `miku-xlsx2md`. |
| `version` | string | `package.json` version used by the CLI or export caller. |
| `output_mode` | string | `display`, `raw`, or `both`. |
| `formatting_mode` | string | `plain` or `github`. |
| `table_detection_mode` | string | `balanced`, `border`, or `planner-aware`. |
| `shape_details` | string | `include` or `exclude`. |

## Date Stability

`created` and `updated` are generation dates. They normally change when the
same Workbook is regenerated on another date.

Tests and fixture generation should avoid full byte-for-byte comparison of
date-bearing Markdown unless the date is fixed.

The core export API supports a `generatedDate` option for deterministic output:

```js
api.createCombinedMarkdownExportFile(workbook, files, {
  generatedDate: "2026-01-02"
});
```

The CLI intentionally does not expose a public `--generated-date` option.

## Agent Reading Guidance

AI agents may use front matter to decide whether the artifact is relevant and
which conversion settings were used.

Do not rely on front matter alone to reconstruct Workbook content. The
converted content lives in the Markdown body under `# Book: ...` and
`## Sheet: ...` sections. Detailed diagnostics may appear in summaries or
future sidecar artifacts rather than in front matter.
